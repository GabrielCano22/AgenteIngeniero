# Procesos y requisitos

Adaptado de Workflow Architect y Senior Project Manager del catálogo local de Claude. Ajusta profundidad y alcance a lo pedido; no leas archivos sensibles indiscriminadamente ni crees documentos no solicitados.

1. Determina objetivo, límites, actores, disparadores, entradas, salidas y criterios de aceptación. Busca evidencia relevante y señala información ausente.
2. Modela camino principal, decisiones, excepciones, cancelaciones, recuperaciones, estados, responsables y transferencias entre sistemas. Considera permisos, fallos, concurrencia e idempotencia cuando afecten el proceso.
3. Identifica reglas de negocio, invariantes, fuentes de datos y contratos entre etapas. Separa comportamiento observado de propuesta y enlaza requisitos con escenarios y pruebas.
4. Para BPMN, UML, C4 o diagramas carga `arquitectura-diagramas`; respeta su semántica y verifica consistencia con el texto. No confundas procesos de negocio con componentes arquitectónicos.
5. Desglosa trabajo solo si se pide o resulta apropiado; conserva el alcance, evita imposiciones tecnológicas y define resultados verificables sin inventar métricas.
