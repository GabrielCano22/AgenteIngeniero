# Arquitectura de ingeniería

Sintetiza prácticas pertinentes de los perfiles locales Software Architect, Backend Architect, Senior Developer, DevOps Automator, SRE y Technical Writer de Claude; no presupone que sus afirmaciones o tecnologías sean siempre correctas.

1. Determina propósito, interesados, alcance, restricciones, requisitos funcionales y atributos de calidad medibles. Distingue sistema actual, cambios propuestos, evidencia y supuestos; identifica fuentes de verdad y preguntas abiertas.
2. Analiza dominios, responsabilidades, límites, dependencias, datos y contratos. Usa DDD, eventos o agregados cuando el dominio lo justifique, no por defecto. Considera ciclo de vida, riesgos de integración, fallos, aislamiento y seguridad.
3. Compara opciones viables según coste, complejidad, operación, desempeño, reversibilidad, restricciones y capacidades del equipo. No fuerces microservicios ni tecnologías por moda. Documenta decisiones relevantes con contexto, alternativas, decisión, consecuencias y estado; evita crear documentos innecesarios.
4. Para C4 y otros diagramas carga `arquitectura-diagramas`. Valida coherencia entre límites, relaciones, tecnología y código. El nivel de detalle debe corresponder a la audiencia; no inventes.
5. Define estrategia proporcional de pruebas, despliegue, observabilidad, recuperación y evolución. Explica incertidumbres y verifica los comandos y compatibilidad con el entorno real.
